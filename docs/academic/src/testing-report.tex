\section{Purpose and Scope}

This document records how ThinkStack is tested, what the tests establish, and
what they currently report. It covers the backend, the interface, the contract
between them, and the packaged application as installed on a user's machine.

It does not yet cover cross-platform verification of the replaced interface or
of the Scribe writing path. Section~\ref{sec:outstanding} states precisely what is outstanding and
why, rather than leaving the omission implicit.

\section{Testing Strategy}

Four layers, each establishing something the layer below it cannot.

\begin{longtable}{@{}p{0.22\linewidth}p{0.30\linewidth}p{0.42\linewidth}@{}}
\caption{Testing layers and what each establishes}\label{tab:strategy}\\
\toprule
\textbf{Layer} & \textbf{Tool} & \textbf{What only this layer can establish} \\
\midrule
\endfirsthead
\toprule
\textbf{Layer} & \textbf{Tool} & \textbf{What only this layer can establish} \\
\midrule
\endhead

Unit (backend) & pytest & That a function computes what it claims, including
  its failure modes. \\
\addlinespace
Unit (interface) & vitest, jsdom & That a component renders and behaves under
  interaction, without a browser. \\
\addlinespace
Contract & pytest, source parsing & That both sides of the API agree,
  parsed from source rather than asserted by hand. \\
\addlinespace
Reachability & live HTTP & That the handlers \emph{run}. Parsing proves the
  paths match; only calling them proves anything executes. \\
\addlinespace
Packaged application & \texttt{validate\_bundle.py} & That the \emph{installed}
  program works. A suite run from a source checkout cannot see what the
  freezer omitted. \\
\bottomrule
\end{longtable}

\evidence{\textbf{Why the last two layers exist.} Version 1.0.0 passed every
test and every build, was published, and did not start: the frozen backend
silently dropped the inference library's shared objects and the embedding
model's data, because neither package ships a hook for the freezer. And when the
interface was replaced, the contract test was found to be hardcoded to the old
directory, the moment the replacement shipped it would have gone on passing
while validating a tree nobody built.}

The curated set was chosen by the authors. The random set was drawn across 15
arXiv subject classifications through the public interface, and scored against
the archive's own catalogue records, so neither the papers nor the expected
answers were selected here.

The first random measurement was \textbf{62.5\%} on all three fields. The whole
difference was three typesetting conventions that had not been examined:

\begin{enumerate}[leftmargin=*]
  \item a physics template spacing a centred author line widely enough to be
        indistinguishable from column separation, so two authors read as five
        fragments and none as a name;
  \item a template running from the affiliations into the abstract with no
        heading, so the search for authors continued into the body and
        collected section headings;
  \item a margin threshold added to discard an archive stamp, which was also
        discarding the first line of any centred title wide enough to begin
        left of it.
\end{enumerate}

Of the 13 remaining failures, \textbf{three are not extraction errors}: the page
reads ``M.~GRENDÁR'' and ``Audrey Quessadda-Vial'' where the archive record
disagrees with the paper itself.

\section{Closing the Cross-Platform Defects}\label{sec:closing}

All four defects from Section~\ref{sec:platforms} were closed before this document was issued.
Each is recorded here with its cause rather than only its symptom, because in
three of the four the symptom named the wrong thing.

\textbf{D-16, the reader on Windows.} The message named a file, which made it
look like a problem with the document, and the tester reasonably deleted the
papers and ingested them again. No paper was involved. Python seeds its media
type table from the Windows registry, which carries no entry for \texttt{.mjs};
the server therefore answered \texttt{text/plain}, and a browser refuses to
execute a module script that is not served as JavaScript. The asset arrived and
the browser declined it. The application now declares the six types a built
interface is served as, before anything can answer a request. Invisible on
Linux and macOS, where the built-in table is correct, which is why every suite
passed while the reader was unusable on one platform in three.

\textbf{D-17, repeated gaps.} Nothing removed duplicates: each entry the model
returned was given a fresh identifier, so two identical descriptions became two
findings, drawn separately and counted separately. Repeats are now merged
rather than discarded, since the second copy often carries evidence the first
does not. The comparison is deliberately narrow, on case and spacing alone: a
looser rule would eventually merge two findings that differ by one word, and
the difference between evaluating on stationary and non-stationary data is the
finding itself.

\textbf{D-18, selecting a node.} A paper is drawn as a point four to eight
units across, and the click target was the drawing, which is six pixels once
the map is scaled to fit. The drawing is unchanged, since larger discs would
turn the plate into a bubble chart. What changed is that an invisible target
carries the selection, and it holds a constant size on screen as the map zooms:

\begin{center}
\small
\begin{tabular}{@{}lrr@{}}
\toprule
& \textbf{Before} & \textbf{After} \\
\midrule
Visible point       & 5.9\,px  & 5.9\,px \\
Selectable area     & 5.9\,px  & 28.0\,px \\
Title selectable    & no       & yes \\
Papers visible at the default view & 22 & 22 \\
\bottomrule
\end{tabular}
\end{center}

Opening the map already zoomed in was considered and rejected: any zoom high
enough to help crops the map, and seeing the whole structure at once is what
the view is for. The title was also inert, which mattered more than the target:
it is roughly eighty pixels wide against a six pixel point, and a reader who
has found the paper they want has almost always found it by reading the title.

\textbf{D-19, the reading surface.} The page was 94\% luminance filling the
screen. It is 89\% now, and the text was pulled back from a contrast ratio of
15:1 to 11.9:1, since near-black on cream is its own fatigue. An intermediate
attempt lowered both the page and the surface beneath it and was rejected on
sight as looking dusty: luminance fell while colour intensity rose, which reads
as dirt rather than as paper. Every step of the text ramp, and both status
colours, were measured against both surfaces and clear the AA threshold.

\section{The Recurring Defect Class}

Five of the defects above, D-01, D-03, D-06, D-07 and D-11, are the same
mistake: \emph{a check that tests for silence, when the failure mode is
confident wrongness}. A guard asking whether a title is empty cannot catch a
title that is wrong. A release asking whether a job failed cannot catch a job
that succeeded into a draft. A dash meaning ``nothing yet'' cannot be
distinguished from a dash meaning ``the request failed''.

The correction is the same in each case: test for the shape of a right answer
rather than for the absence of a wrong one.

\section{A Defect No Test Environment Could Have Caught}\label{sec:nolayout}

One defect from the citation work is recorded for the method rather than the
cause, because it changes what the interface suite can be relied on to prove.

The citation list did not appear. Every automated test passed, including tests
that type into an editor and assert that the list opens with the expected rows,
because those tests run in a simulated document object model that computes no
layout: every element it reports is at the origin and has no size. Driving the
real application and reading the element's position back showed the list
present, populated with all twenty papers, and drawn 1382 pixels down a window
1000 pixels tall, inside a region that hides rather than scrolls what exceeds
it. A second cause was found the same way: the compiled document displayed
beside the editor is drawn above the list and concealed the column holding the
citation keys.

The consequence for this document is narrow and should not be overstated. The
interface suite proves that components mount, that state changes as expected,
and that the calls they make exist. It cannot prove that anything is visible.
Screenshots taken from the running application, and the platform verification
in Section~\ref{sec:outstanding}, are the only evidence of that, which is part of why the
outstanding items below are treated as blocking rather than cosmetic.

\section{Verification Status}\label{sec:outstanding}

Every feature described in the project report is implemented, and every defect
found during the testing phase is fixed. The application is verified on all
three platforms it ships to.

All automated suites pass on Linux, which is the development platform: 1\,328
tests across four layers, of which one is skipped rather than run. That test asks the running server what media type it
gives a JavaScript module, which is the fix for D-16; it needs a built
interface to serve, and skips rather than pretending to pass when there is
none. The application has
been released publicly through sixteen versions, and version 2.3.0 has been
installed and exercised by testers on macOS and Windows as recorded in
Section~\ref{sec:platforms}. Four defects came out of that round, D-16 to D-19. None is a
regression introduced by the release: all four were present in earlier builds
without having been observed. All four are now fixed, as recorded in
